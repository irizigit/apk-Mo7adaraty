# توقيع APK الدائم لتحديث «محاضراتي»

النسخ السابقة من سير العمل كانت تنشئ مفتاح توقيع جديداً لكل بناء. لا يمكن لـAndroid تثبيت APK موقّع بمفتاح مختلف فوق تطبيق موجود؛ وقد يضطر المستخدم وقتها إلى إلغاء تثبيت التطبيق، ما يمسح ملفات المحاضرات المخزنة داخله.

من الآن فصاعداً، يستخدم سير العمل مفتاح Release واحداً ثابتاً. بعد تثبيت أول APK مبني بهذا المفتاح، ستبقى الملفات والمجلدات وبيانات التطبيق عند تثبيت الإصدارات اللاحقة، بشرط بقاء اسم الحزمة `com.app.mo7adaratynova` نفسه وزيادة `versionCode` في كل إصدار.

## إنشاء المفتاح مرة واحدة

نفذ الأمر التالي على جهاز موثوق به، وليس في مستودع عام:

```bash
chmod +x scripts/create-release-keystore.sh
./scripts/create-release-keystore.sh ~/mo7adaraty-release.keystore mo7adaraty
```

سيطلب `keytool` كلمة مرور ملف المفتاح وكلمة مرور المفتاح نفسه. استخدم قيماً قوية واحفظ الملف وكلمات المرور في مدير كلمات مرور أو نسخة احتياطية مشفرة. فقدان هذا المفتاح يمنع إنشاء تحديثات متوافقة مع التطبيق المنشور.

## إضافة أسرار GitHub

من صفحة المستودع افتح **Settings → Secrets and variables → Actions** ثم أنشئ القيم التالية:

| اسم السر | القيمة |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | الناتج الكامل للأمر `base64 -w 0 ~/mo7adaraty-release.keystore` |
| `ANDROID_KEYSTORE_PASSWORD` | كلمة مرور ملف المفتاح |
| `ANDROID_KEY_ALIAS` | `mo7adaraty` أو الاسم الذي اخترته |
| `ANDROID_KEY_PASSWORD` | كلمة مرور المفتاح |

لا تضع ملف keystore أو كلمة المرور أو النص Base64 في GitHub أو في لوحة الموقع أو داخل التطبيق.

## تنبيه مهم للإصدارات المنشورة سابقاً

إذا كان المستخدمون ثبّتوا APK قديماً موقّعاً بمفتاح GitHub Actions المؤقت، فلن يمكنهم التحديث مباشرة إلى أول إصدار دائم؛ سيحتاجون إلى تصدير ملفاتهم أو مشاركتها ثم إلغاء تثبيت النسخة القديمة وتثبيت أول APK الدائم. بعد هذه الخطوة الانتقالية الواحدة فقط، تحفظ جميع التحديثات التالية البيانات.
