# منصة تنزيل وإدارة «محاضراتي»

هذه الحزمة جاهزة للرفع إلى المسار `https://irizi.unaux.com/mo7adaraty-apk/`. تقدم صفحة تنزيل عربية، ولوحة إدارة للإصدارات والروابط والمرايا والإعلانات والإشعارات، وواجهات API التي سيستخدمها تطبيق محاضراتي لاحقاً.

## قبل الرفع

1. من لوحة Unaux، أنشئ قاعدة MySQL جديدة مخصصة لمحاضراتي.
2. افتح phpMyAdmin الخاص بالقاعدة واستورد ملف `schema.sql` كاملاً.
3. انسخ `config/config.example.php` باسم `config/config.php` على جهازك.
4. املأ في `config.php` بيانات MySQL التي أعطتك إياها Unaux، ثم أنشئ `analytics_salt` عشوائياً بطول 32 حرفاً أو أكثر.
5. اختر كلمة مرور قوية للحساب الأول في `first_admin_password`. لا تستخدم كلمة مرور افتراضية أو قصيرة.

> لا ترفع `config.example.php` بعد نسخه إلى `config.php` بالبيانات الحقيقية داخل مستودع عام. ملف `config.php` مستثنى من Git عمداً.

## الرفع

ارفع **محتويات** مجلد `mo7adaraty-apk` إلى:

```text
/htdocs/mo7adaraty-apk/
```

عند اكتمال الرفع، يجب أن تكون هذه الملفات متاحة:

```text
https://irizi.unaux.com/mo7adaraty-apk/
https://irizi.unaux.com/mo7adaraty-apk/admin/login.php
https://irizi.unaux.com/mo7adaraty-apk/version.json
```

اختر PHP 8.1 أو أحدث من لوحة الاستضافة إن كان خيار الإصدار متاحاً.

## أول دخول ولوحة الإدارة

1. افتح `admin/login.php` وسجّل دخولك باستخدام `first_admin_username` و`first_admin_password` اللذين عينتهما في `config.php`.
2. بعد التأكد من الدخول، غيّر قيمة `first_admin_password` في `config.php` إلى سلسلة فارغة. يبقى حسابك محفوظاً في قاعدة البيانات بكلمة مرور مشفرة ولا يحتاج هذا الحقل لاحقاً.
3. من صفحة **الإصدارات** أضف رقم الإصدار ورقم البناء وسجل التغييرات وروابط التنزيل.
4. اجعل رابط GitHub Releases رابطاً أساسياً، ثم أضف Google Drive وMediaFire كمرايا اختيارية.
5. فعّل خيار **انشر الإصدار الآن**. يحدث الموقع ملف `version.json` تلقائياً ليقرأه التطبيق.

## صيغة الإصدار الصحيحة

| الحقل | مثال | قاعدة الاستخدام |
|---|---|---|
| اسم الإصدار | `1.1.1` | يظهر للمستخدم فقط |
| رقم البناء | `3` | عدد صحيح يزداد في كل APK جديد، وهو الذي تقارنه المنصة والتطبيق |
| التحديث الإلزامي | مفعّل أو غير مفعّل | لا تستخدمه إلا عندما يمنع خطأ قديم التطبيق من العمل |

## الإشعارات

تحتاج الإشعارات الفورية إلى أن يضيف التطبيق رمز Expo Push لكل جهاز موافق. بعد إضافة هذه الميزة في التطبيق وبناء APK جديد، ستظهر الأجهزة المصرح لها في لوحة الإدارة. من صفحة **الإشعارات** اكتب عنواناً ونصاً ورابطاً اختيارياً ثم أرسلها.

تحتاج هذه العملية أيضاً إلى مشروع Expo حقيقي ومعرّف `projectId` خاص به، وإلى إعداد Firebase Cloud Messaging V1 داخل المشروع نفسه. ضع معرّف مشروع Expo في `app.config.ts` ضمن `extra.eas.projectId`، ثم أضف بيانات FCM V1 في حساب Expo قبل بناء APK. من دون هذا الإعداد يمنح Android إذن الإشعارات، لكن لا يستطيع التطبيق إنشاء رمز Expo Push ولا تستطيع لوحة الموقع استهداف الجهاز.

تبقى الإعلانات داخل التطبيق مستقلة عن FCM: يقرأ التطبيق `api/announcement.php` عند فتحه. كما يسجل الإصدار المصحح كل تثبيت مجهول في `api/ping.php` عند التشغيل حتى إذا لم يفعّل المستخدم الإشعارات.

## ما لا تفعله الحزمة

- لا ترفع ملف APK إلى Unaux ولا تحفظه هناك؛ إذ تعتمد صفحة التنزيل على روابط GitHub Releases وGoogle Drive وMediaFire.
- لا تعرف المستخدمين بأسمائهم ولا تجمع رقم هاتف أو معرف جهاز النظام. مقياس الأجهزة النشطة اختياري ومجهول.
- لا تثبّت تحديث Android تلقائياً؛ تفتح للمستخدم صفحة التنزيل ويؤكد التثبيت بنفسه.

## فحص سريع بعد النشر

افتح الصفحة الرئيسية، ثم اضغط زر تنزيل من كل مرآة منشورة، وجرّب الدخول إلى لوحة الإدارة. إذا ظهرت رسالة إعداد `config.php`، تأكد من اسم الملف ومساره ومن بيانات قاعدة MySQL. إذا ظهرت صفحة بيضاء، راجع سجل أخطاء PHP في لوحة الاستضافة.
